# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Yumit** — tagline: *Shop smarter. Eat better.*

Yumit is a UK-focused household grocery intelligence PWA. Users scan receipts, get nutritional analysis, generate shopping lists, and receive meal/batch cooking suggestions — all powered by Claude AI. All data is stored in localStorage (no database). The app is UK-specific: GBP only, UK supermarkets only.

"Yumit" must appear in the browser tab title, PWA manifest, and onboarding screen with the tagline directly beneath it.

## Development Commands

```bash
npm run dev          # Start both client (port 5173) and server (port 3001) concurrently
npm run dev:client   # Vite dev server only
npm run dev:server   # Express server only
npm run build        # Production build to /dist
npm run lint         # ESLint (flat config)
```

No test framework is configured yet.

## Environment

Create a `.env` file with:
```
CLAUDE_API_KEY=your_key_here
PORT=3001
```

The user's own API key (stored in localStorage as `yumit_api_key`) takes priority over the server env var. The Vite dev server proxies `/api/*` to `http://localhost:3001`.

## Architecture

### Auth/Onboarding Gates (App.jsx)

Before the main app renders, two gates are checked in sequence:
1. No `yumit_api_key` in localStorage → show `ApiKeySetupPage`
2. No household profile in `yumit_profile` → show `OnboardingPage`
3. Both present → render main app with React Router

### Claude API Flow

All AI calls go through the Express backend (`server/routes/claude.js`). Every request body includes a `systemPrompt` built by `src/utils/systemPrompt.js` using the household's profile. The frontend service (`src/services/claude.js`) calls these endpoints, and `src/hooks/useClaudeAI.js` wraps them as React hooks.

**Backend endpoints (all POST `/api/claude/*`):**
- `/parse-receipt` — Vision OCR on base64 image → `{ items[], total, date, store }`
- `/analyze-nutrition` — Score basket → `{ score (0-100), grade (A-D), flags, gaps }`
- `/batch-cooking` — Generate 2 recipes → `{ recipes[] }`
- `/smart-swaps` — Suggest alternatives → `{ swaps[], totalSaving, healthTips }`
- `/generate-shopping-list` — Weekly meal plan → `{ selectedMeals, shoppingList (by aisle), mealPlan }`
- `/import-recipe` — Scrape/parse recipe from URL or pasted text

**JSON parsing:** Claude responses sometimes wrap JSON in markdown code blocks. The server uses a regex fallback to extract JSON from code blocks when `JSON.parse` fails directly.

### Data / localStorage Keys

All keys use the `yumit_` prefix. Never use the old `fb_` prefix.

| Key | Contents |
|-----|----------|
| `yumit_api_key` | User's Anthropic API key |
| `yumit_profile` | Household profile (members, budget, supermarket, batch cooking settings) |
| `yumit_usage` | Scan counts and nudge tracking |
| `yumit_shopping_history` | Array of past shopping records |

### Household Profile System (`src/services/profile.js`)

The profile object stored in `yumit_profile` contains:
```js
{
  householdName,
  members: [{ name, lifeStage, notes: [] }],
  budget: { min, max },       // weekly GBP range
  supermarket,
  batchCooksPerWeek,
  daysPerBatch,
}
```

**Life stages** with portion multipliers used by `calculateTotalPortions()`:

| Key | Label | Multiplier |
|-----|-------|------------|
| `toddler` | Toddler (under 5) | 0.4 |
| `child-5-10` | Child (5–10) | 0.7 |
| `young-teen` | Young Teen (11–16) | 1.0 |
| `adult` | Adult (17–64) | 1.0 |
| `senior` | Senior (65+) | 0.85 |

**Member notes** (dietary/health flags): `vegetarian`, `vegan`, `pregnant`, `breastfeeding`

**Usage nudge logic** (`shouldShowNudge`): returns `'modal'` on scan 10 (if no own API key and nudge not yet shown), then `'banner'` every 10 scans after that.

**Children's Meals section** is only rendered when the household profile includes at least one member with a child life stage (`toddler`, `child-5-10`, or `young-teen`).

### Dynamic System Prompt Builder (`src/utils/systemPrompt.js`)

`buildSystemPrompt(profile)` is called on the frontend before every API request and included in the request body as `systemPrompt`. It composes:

1. **Household block** — name, supermarket, budget range, batch cooking schedule
2. **Members block** — one line per member: name, life stage label, age range, notes
3. **Nutritional priorities block** — generated by `getNutritionalPriorities(members)`, which maps life stages and notes to specific guidance strings:
   - `toddler` → salt monitoring + iron
   - `child-5-10` / `young-teen` → calcium, vitamin D, protein, iron, varied veg
   - `senior` → vitamin D and fibre
   - `pregnant` note → folate, iron, oily fish; lists foods to avoid
   - `breastfeeding` note → calories and hydration
   - `vegan` note → B12, complete protein, iron (overrides vegetarian if both present)
   - `vegetarian` note → B12 and complete protein sources
4. **Hard rules** — UK only, GBP only, warm/friendly tone, use member names; batch cooking recipes must automatically scale to household size × `daysPerBatch`

If no profile exists, a minimal fallback prompt is returned instead.

### Numeric-First Dictionary Matching (`src/data/productDictionary.js`)

Aldi receipts print 5–6 digit numeric product codes alongside abbreviated text labels. `translateCode(code, customDictionary)` resolves them with a strict priority order:

1. Custom numeric codes (user-added overrides)
2. Default numeric codes (`numericCodeDictionary` — 5–6 digit keys)
3. Custom text codes (user-added overrides, uppercased)
4. Default text codes (`textCodeDictionary` — uppercased abbreviations)
5. Original code unchanged (fallback)

`isNumericCode(code)` uses `/^\d{5,6}$/` to distinguish the two lookup tables. `defaultProductDictionary` exports both tables as `{ numeric, text }` for passing as a unit. Custom dictionaries (stored in profile) follow the same `{ numeric, text }` shape so they can be merged cleanly.

### Vercel Deployment

No `vercel.json` exists yet. The app requires two deployment targets on Vercel:

- **Frontend**: Vite build output (`/dist`) served as static files
- **Backend**: Express server (`server/index.js`) — Vercel requires this to be exported as a serverless function rather than calling `app.listen()`

To deploy, the Express server must be refactored: remove the `app.listen()` call and add a default export of the `app` instance. Then `vercel.json` routes all `/api/*` requests to the serverless function and everything else to the Vite-built static files:

```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "rewrites": [
    { "source": "/api/(.*)", "destination": "/server/index.js" },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

Set `CLAUDE_API_KEY` as an environment variable in the Vercel project dashboard (not in `.env`, which is gitignored).

## Key Conventions

- **App name**: Yumit. **Tagline**: Shop smarter. Eat better.
- **UI copy**: always "household", never "family"
- **Currency**: GBP (£) only, never USD
- **Supermarkets**: UK-specific only
- **localStorage prefix**: `yumit_` — never use the old `fb_` prefix
- **Claude model**: `claude-sonnet-4-20250514` (defined in `server/routes/claude.js`)
- **Shopping items**: `{ code, name, quantity, price }` where `code` is product ID
- **Static product data**: lives in `src/data/` (aisle categories, default meals, Aldi product dictionary)
- **Shopping list**: must always display an estimated total alongside the household's weekly budget
- **Batch cooking**: recipes must auto-scale portions to household size × `daysPerBatch`
- **Definition of done**: run `npm run build` locally and confirm it succeeds before considering any feature complete

## Non-Food Item Handling

Non-food items on receipts (cleaning products, toiletries, pet food, candles, and similar) must be:
- **Flagged** visually in the scanned items list
- **Excluded** from all nutrition scoring calculations
- **Included** in the spend total (they cost money)

The `/analyze-nutrition` endpoint and any client-side nutrition logic must filter these out before scoring. The receipt parser should tag them with `nonFood: true`.
